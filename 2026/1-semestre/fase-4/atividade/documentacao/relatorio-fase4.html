1. Introdução

A Vinheria Agnello iniciou sua transformação digital com a definição do problema de negócio e da experiência desejada para seus clientes. Nas fases anteriores foram desenvolvidos o conceito do e-commerce, as interfaces web, um catálogo conectado a banco de dados e uma análise preditiva de vendas. A quarta fase amplia esse ecossistema por meio de um controle de estoque persistente, capaz de armazenar os produtos mesmo depois que a aplicação é encerrada.

A persistência é essencial porque o estoque representa o estado operacional da vinheria. Informações como nome do vinho, safra, origem, preço e quantidade disponível não podem depender apenas da memória temporária do programa. Sem armazenamento permanente, os dados seriam perdidos a cada reinicialização, comprometendo consultas, reposição de itens e decisões de venda.

A solução foi dividida em dois módulos independentes. O primeiro é um aplicativo Android escrito em Kotlin, com interface Jetpack Compose e banco local Room. O segundo é uma aplicação console em C#, com repositório que serializa os produtos em um arquivo JSON. Os dois módulos implementam as operações Create, Read, Update e Delete, conhecidas pela sigla CRUD.

3. Módulo Android com Room

3.1 Room e arquitetura adotada

Room é uma biblioteca do Android Jetpack que fornece uma camada de abstração sobre o SQLite. Ela permite representar tabelas por meio de classes Kotlin, validar consultas SQL durante a compilação e concentrar o acesso aos dados em interfaces DAO. A solução possui entidade, DAO, banco, repositório, ViewModel e interface Compose. Essa separação reduz o acoplamento entre a tela e o armazenamento.

3.4 DAO e operações CRUD

@Dao
interface ProdutoDao {
    @Query("SELECT * FROM produtos ORDER BY nome ASC")
    fun observarTodos(): Flow<List<Produto>>

    @Query("SELECT * FROM produtos WHERE id = :id LIMIT 1")
    suspend fun buscarPorId(id: Int): Produto?

    @Insert suspend fun inserir(produto: Produto): Long
    @Update suspend fun atualizar(produto: Produto): Int
    @Delete suspend fun excluir(produto: Produto): Int
}

O DAO reúne as quatro operações exigidas. A listagem retorna um Flow, fazendo a interface reagir automaticamente sempre que o conteúdo do banco muda. As operações de escrita são suspensas para não bloquear a interface do aplicativo.

4. Módulo de persistência em C#

4.1 Escolha da abordagem

O módulo C# utiliza um arquivo JSON porque essa abordagem demonstra persistência real sem exigir servidor, banco externo ou pacote adicional. A biblioteca System.Text.Json faz parte da plataforma .NET e converte objetos C# para uma representação textual estruturada. A solução continua extensível: a interface do repositório permite substituir o JSON por SQLite ou Entity Framework no futuro sem alterar o menu.

4.2 Classe Produto e contrato do repositório

public sealed class Produto
{
    public int Id { get; set; }
    public string Nome { get; set; } = string.Empty;
    public string Tipo { get; set; } = string.Empty;
    public int Safra { get; set; }
    public int Quantidade { get; set; }
    public decimal Preco { get; set; }
    public string Origem { get; set; } = string.Empty;
    public string Descricao { get; set; } = string.Empty;
}
public interface IProdutoRepository
{
    IReadOnlyList<Produto> Listar();
    Produto? BuscarPorId(int id);
    Produto Cadastrar(Produto produto);
    bool Atualizar(Produto produto);
    bool Excluir(int id);
}

4.3 Repositório JSON

Ao iniciar, o repositório cria a pasta e o arquivo quando necessário. As operações de cadastro, atualização e exclusão chamam o método de gravação imediatamente. O arquivo é escrito primeiro com extensão temporária e depois substitui o original, reduzindo o risco de conteúdo parcialmente gravado. Um JSON inválido gera uma mensagem explícita em vez de apagar silenciosamente os dados.

6. Conclusão

A fase 4 introduz persistência de dados no controle de estoque da Vinheria Agnello. O módulo Android usa Room para oferecer um banco local estruturado, com atualização reativa da interface. O módulo C# aplica o padrão de repositório e salva os produtos em JSON. Em ambos os casos, o CRUD permite cadastrar novos itens, consultar o estoque, corrigir informações e remover registros que deixaram de ser utilizados.

Essas funcionalidades reduzem o risco de perda de informações e formam uma base técnica para evoluções futuras, como sincronização com o e-commerce, controle de entradas e saídas, alertas de estoque mínimo e integração com relatórios de vendas. A separação em camadas também facilita testes e a substituição do mecanismo de armazenamento quando o projeto crescer.
